# ESP32, лидар и светодиодное кольцо

## Что нужно

- ESP32;
- круговой лидар ROSiK/Camsense-совместимого формата;
- кольцо WS2812 на 8 светодиодов;
- USB-кабель для ESP32;
- общий источник питания, соответствующий вашей сборке;
- общая земля между ESP32, лидаром и остальной электроникой.

## Подключение

| Сигнал | ESP32 | Направление |
|---|---:|---|
| TX лидара | GPIO16 | LiDAR → ESP32 |
| RX лидара | GPIO17 | ESP32 → LiDAR; в текущем проекте обычно не нужен |
| DATA кольца WS2812 | GPIO14 | ESP32 → кольцо |
| mask UART TX | GPIO4 | ESP32 → внешнее устройство, опционально |
| GND | GND | общая земля |

Лидар работает через `Serial2` на скорости **115200 бод**. Компьютер получает бинарный поток через основной USB/Serial ESP32 на скорости **460800 бод**.

## Прошивка

Откройте в Arduino IDE:

```text
firmware/rosik_lidar_uart/rosik_lidar_uart.ino
```

Понадобится:

1. установленный пакет плат ESP32;
2. библиотека `FastLED`;
3. выбранная ESP32-плата;
4. выбранный COM/TTY-порт.

После прошивки **не открывайте Serial Monitor одновременно с Python или ROS 2**: последовательный порт может использовать только одна программа.

## Что делает прошивка

- синхронизируется по заголовку пакета лидара `55 AA 03 08`;
- читает 8 измерений в каждом пакете;
- интерполирует углы между начальным и конечным углом пакета;
- собирает полный оборот 360°;
- формирует пакет расстояний;
- формирует companion-пакет нативной intensity;
- считает CRC16;
- передаёт данные компьютеру;
- обновляет 8 секторов кольца WS2812;
- при необходимости передаёт 1-байтовую секторную маску через GPIO4.

## Почему используются увеличенные UART-буферы

Прошивка передаёт полный скан и intensity на высокой скорости. Чтобы запись в USB/UART не блокировала обработку входящего потока лидара, до `begin()` задаются увеличенные буферы:

```text
Host TX: 4096 байт
LiDAR RX: 4096 байт
```

Это важно для стабильной работы полного скана.

## Первичная проверка после прошивки

Не запускайте ROS 2 сразу. Сначала:

```powershell
python tools\hardware_smoke.py COM6 --seconds 10
```

или:

```bash
python3 tools/hardware_smoke.py /dev/ttyUSB0 --seconds 10
```

Ожидается отсутствие CRC/header ошибок и совпадение scan/intensity по sequence.
