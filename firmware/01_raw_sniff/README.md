# 01. Первый запуск: чтение сырых данных лидара

Этот скетч нужен для самой первой проверки лидара. Он ничего не фильтрует и не преобразует: байты, пришедшие от лидара по UART2, выводятся в USB Serial в шестнадцатеричном виде.

Файл прошивки: [`RosikLidarRawSniff.ino`](RosikLidarRawSniff.ino)

## Подключение

| Лидар | ESP32 |
|---|---|
| TX | GPIO16 (RX2) |
| RX | GPIO17 (TX2, обычно не требуется) |
| GND | GND |
| Питание | согласно требованиям конкретного модуля лидара |

UART лидара работает на **115200 бод**.

После прошивки откройте Serial Monitor на **115200 бод**. В исправно работающем потоке регулярно должна встречаться последовательность заголовка:

```text
55 AA 03 08
```

Скетч печатает каждый байт отдельной строкой, например:

```text
0x55
0xAA
0x03
0x08
...
```

## Структура исходного пакета лидара

Один пакет содержит **36 байт**:

```text
55 AA 03 08                      4 байта  заголовок
speed                            2 байта  служебное поле скорости
start_angle                      2 байта  начальный угол
point[0] ... point[7]           24 байта  8 точек × 3 байта
end_angle                        2 байта  конечный угол
tail                             2 байта  служебные байты пакета
```

Каждая из 8 точек:

```text
distance_low                     1 байт
 distance_high                   1 байт
 intensity                       1 байт
```

То есть расстояние хранится как `uint16 little-endian`, а интенсивность отражения — как `uint8`.

Угол декодируется формулой:

```text
angle_deg = (raw_angle - 0xA000) / 64
```

В одном пакете находятся 8 измерений между `start_angle` и `end_angle`. Начальная и конечная точки входят в эти восемь измерений, поэтому при интерполяции используется шаг:

```text
(end_angle - start_angle) / 7
```

## Что считать успешной проверкой

- поток идёт непрерывно;
- регулярно встречается `55 AA 03 08`;
- после поворота/перемещения объектов байты данных меняются;
- ESP32 не перезагружается и поток не замирает.
